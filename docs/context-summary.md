# track Context Summary

## Что это за проект

`track` - личный трекер задач с живым прогрессом, видимыми паузами и компактным списком задач.

Главная идея:
- у задачи есть течение во времени
- progress bar обновляется в реальном времени
- паузы видны прямо на bar
- детали задачи открываются во всплывающем окне

## Текущий технический подход

Проект сейчас сделан как zero-build web MVP без зависимостей:
- `index.html`
- `src/styles.css`
- `src/main.js`
- хранение в `localStorage`

Причина такого выбора:
- в среде нет `node` и `npm`
- нужен был минимальный кроссплатформенный MVP без сборки

## Ключевые продуктовые правила

### Типы задач

Есть 2 типа:
- `Со сроком`
- `Фоновая`

### Режим срока для задач `Со сроком`

Используется строгая логика `ИЛИ`:
- `Дата`
- `План`

Нельзя использовать оба режима одновременно.

#### Режим `Дата`
- указывается только календарная дата
- без времени суток

#### Режим `План`
- указывается количество
- указывается единица
- единицы:
  - минуты
  - часы
  - дни
  - недели
  - месяцы
  - годы

### Фоновые задачи

Фоновая задача:
- без срока
- без плановой длительности
- с учетом работы, пауз и событий

### Правила действий

- `Старт` без комментария
- `Продолжить` без комментария
- `Пауза` только с обязательной причиной
- `Завершить` только с обязательной причиной

### Progress bar

- каждая задача в списке занимает 2 строки
- строка 1: информация, статусы, действия
- строка 2: только progress bar
- паузы всегда показываются черным цветом

#### Для задач `Со сроком` + `План`
- bar строится по плановой длительности

#### Для задач `Со сроком` + `Дата`
- bar строится по движению к дедлайну

#### Для `Фоновой` задачи
- bar показывает ленту активности и пауз
- без дедлайна

В `src/main.js` используется базовая модель задачи:
- `id`

- `type`

- `plannedAmount`
- `plannedUnit`
- `description`

- `createdAt`
- `history[]`

События:
- `created`
- `started`
- `paused`
- `resumed`
- `completed`

## Что уже решено по UX

- список задач должен быть максимально компактным
- детали не должны раздувать строку задачи
- подробности вынесены в модалку
- метрики уже видны в строке и не должны дублироваться в модалке
- в модалке должны быть:
  - описание
  - контекст/заметки
  - причина последней паузы
  - причина завершения
  - история событий

## Что еще не реализовано полноценно

- возможную сортировку

- тестирование крайних случаев
